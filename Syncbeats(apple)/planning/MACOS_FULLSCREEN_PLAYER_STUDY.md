# Full-screen listening room study

Current HTML: `macos-fullscreen-player.html`. Prior minimal direction retained as `macos-fullscreen-player-v1.html`. The second direction was approved and ported to SwiftUI on `macos-dev`.

The user found the first prototype old-fashioned and too minimal, and requested places for lyrics, queue, and devices. Full-screen still has no macOS title bar or traffic lights.

The new wide layout pairs a substantial album cover and track identity with a dedicated detail pane. A persistent Lyrics / Queue / Devices tab switcher changes that pane. Lyrics use large line-by-line text with a current-line highlight, and selecting a line seeks the timeline. Queue shows the current item and upcoming tracks; selecting a track updates cover and identity. Devices lists the Mac and connected outputs with individual volume controls and a pairing entry point. A separate bottom dock retains artwork, Play/Pause, previous/next, shuffle/repeat, timeline, and system volume while browsing the details.

Compact windows keep the artwork and dock in place; detail tabs open a panel over the artwork. Only the detail content scrolls. Short landscape windows retain the split layout. Artwork only is an optional preview mode that hides the detail pane, room information, and dock; Escape restores them. Escape also closes compact detail panels. Tabs support arrow-key, Home, and End navigation.

Ambient colors are extracted from embedded album covers. Soft curved shapes drift and respond to bass/loudness when local audio is loaded; Reduced Motion stops the drift. The preview bar holds prototype controls outside the player, so browser full-screen contains only the player.

Fixtures are visibly labeled. Lyrics are original sample text for layout, not actual lyrics for F1, Tycho, or Khruangbin. Devices and room information are illustrative and are not connected to a live room; remote device sliders only change the prototype. The Mac slider also controls a loaded audio file. Load audio plays a chosen file locally through Web Audio; the file stays on the device. Without a loaded file, Play advances a demonstration timeline with no sound or fabricated beat signal.

Validation: 39 Chromium checks passed: artwork/tabs/dock bounds; each detail pane at 1440×900, 1280×720, 960×720, 720×560, 420×660, and 390×500; pane separation from playback controls; lyric seeking/highlighting; Mac volume linkage; queue track switching and decoded covers; real local AAC playback with ambient energy; artwork mode/restoration; keyboard tab switching; and absence of script errors. Embedded covers avoid external requests. Screenshot forwarding still returns blank images, so subjective visual acceptance belongs to the inline review.

Native follow-up after review: remove title-bar chrome in full-screen, port the composition and detail-pane behavior, connect the existing shared queue/device state, and integrate a lyrics provider with an explicit instrumental/unavailable state. Native playback must continue using authoritative room time. Sample lyrics and fabricated device statuses must never be ported as real data.

## Native implementation

Window title-bar buttons are hidden. Existing room queue commands, participant volume, shared timeline, and ambient renderer are reused.

Player entry correction: Home artwork, the bottom mini-player, and floating-player expansion now open the approved full-screen player directly on macOS. The mini-player button is labeled Open full-screen player. Previously these routes opened the older in-window layout and required a second expand action. Xcode Build only compiles; Run launches the app. During diagnosis two app processes were running from the same build folder; the stale instance was quit. The corrected Debug build passed and the bottom player button was verified in the single remaining Xcode-launched instance, opening Lyrics/Queue/Devices with the shared timeline and no title-bar buttons.

`RoomLyrics.swift` queries the same LRCLIB provider used by the web app. It matches cleaned track title, resolved artist, and duration, rejects unrelated versions, parses timestamped LRC including multiple timestamps and offsets, and exposes instrumental, plain, unavailable, and retry states. Track/duration task identity and request generations prevent stale results. Synced lines follow room time and support seeking; Browse lyrics pauses following. No sample lyrics or devices are used natively.

The selected Lyrics tab remains the navigation label. Follow/Browse controls are replaced by automatic following: user scrolling suspends centering and reveals Back to live; activating it recenters the current line. ## Graph equalizer and island hover

The user's clarification referred to the equalizer type, not typography. Lyrics typography stays unchanged. The equalizer replaces slider rows with a curved response graph and five draggable gain points, presets, reset and bypass. Keyboard arrows and accessible increment/decrement actions adjust gains. Behind the response curve, 24 log-spaced spectrum bars come from a fixed-size Accelerate FFT of rendered Mac audio. Silence and pause produce a quiet graph; animation is not simulated from playback time. The equalizer is reachable inside the expanded island and through the full-screen player's existing equalizer button.

The camera-safe island has three states: a resting cap only 44 points wider than the camera with a 2-point bottom lip, a hover cap 112 points wider with a 10-point lip, and click-expanded controls. Hover motion shares the panel animation clock, grows around the center and stays anchored to the screen top. Resting shadow is removed. The expanded panel has extra height for the equalizer entry. Leaving/unfocusing closes it; the equalizer popover temporarily keeps the island open and dismissal restores auto-close.

Validation: final native Debug build passed, 56 room/notch checks passed, and 48 native audio checks passed including real room fixtures, known-tone FFT detection, silence/reset behavior, rendered equalizer response, and bypass. The graph rendered offscreen. Live app checks confirmed graph controls instead of sliders, presets and accessible gain adjustment, island expansion, island equalizer access and dismissal/auto-close. Presets were returned to flat/bypassed after verification. Actual pointer-hover dimensions were checked through geometry assertions; screenshot forwarding did not support a visual dimension comparison with the attachments.

Hover refinement: the user clarified that hover should be a very subtle zoom of the same island and content, without repositioning. Hover now scales both dimensions by 1.025 around the same top-center anchor, adding about 6 points of width and less than 1 point of height for the preview notch. The entire cap content scales as one group; artwork no longer resizes independently or causes internal reflow. Hover adds no shadow. Click expansion remains separate. Debug build and 56 room/notch checks passed; the final app was relaunched. Geometry assertions cover scale and anchoring; visual comparison remains limited by attachment/screenshot forwarding.

## Core Audio priority and spectrum response

The asynchronous renderer now uses Default QoS, matching the Core Audio control threads that AVAudioEngine.start() waits on. Engine setup remains on its serial worker, separate from the main thread and audio render callback. This addresses the reported User-initiated-to-Default priority inversion; Xcode Thread Performance Checker has not been rerun to prove the warning is absent at runtime.

The spectrum previously analyzed only the first 1024 frames of each 2048-frame tap. A ring buffer now consumes every frame with 50% overlapping FFT windows, then applies sample-rate-based attack/release smoothing. The display interpolates the real 24-band values at animation frames, clears on pause, and respects Reduce Motion. UI reads use a separate short publication lock; the render tap skips publication if that lock is busy instead of waiting on the UI reader.

Validation: Debug macOS build succeeded, 52 native audio checks and 56 room/notch checks passed. Audio checks cover a tone present only in the second half of a tap, interpolated attack/decay, pause clearing, equalizer processing/bypass, and real Socket.IO scheduling, seek, pause/resume and reconnect against local fixtures. A fixed-delay seek assertion failed under concurrent build load; it now waits for the asynchronous position publication within a bounded interval. In the relaunched app, Play/Pause changed correctly, the duration advanced, and the equalizer exposed Live audio spectrum during playback. Screenshot transport prevented a reliable visual judgement of smoothness.

## Account monogram and Home header

The signed-in header uses a 32-point circular name monogram with gold initials and no dropdown indicator. Clicking it opens the native Profile, Settings and Log out menu. Profile shows account identity and links to the existing music-interests editor. Settings uses persisted appearance and Dynamic Island visibility preferences. Log out uses AppModel.signOut and disconnects the room only after successful session clearing. The Home three-dot menu was removed; reconnect remains a contextual button when the connection fails.

Validation: macOS Debug build succeeded.
